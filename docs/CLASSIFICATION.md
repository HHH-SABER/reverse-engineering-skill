# 分类与命名规则

两条轴分开管：

| 轴 | 记在哪 | 回答什么 |
|---|---|---|
| **目录轴** | 文件系统：`skills/<skill-name>/` | 这个技能的文件在哪 |
| **分类轴** | [`CATALOG.md`](../CATALOG.md) 的「代号」列 | 这个技能属于哪一类 |

## 目录轴：一层，平铺

```
skills/
├── _template/                     ← 新技能骨架（下划线前缀 = 非技能）
├── reverse-engineering/
└── <你的下一个技能>/              ← 平级，不再分级
```

一个技能一个目录，目录内结构固定：

```
<skill-name>/
├── SKILL.md          ← 必需。唯一入口，frontmatter 必填 name + description
├── README.md         ← 建议。给人看：这个技能解决什么问题、怎么用
├── CHANGELOG.md      ← 建议。语义化版本 + 日期 + 改了什么
├── references/       ← 可选。按主题分文件的参考资料
└── scripts/          ← 可选。可直接运行的工具脚本
```

### 为什么不用分类子目录

直觉做法是 `skills/逆向工程/xxx/`，但这样有三个代价：

1. **改分类 = 移动目录** → git 里变成删除+新增，历史断裂，外部链接与引用路径全断。
2. **技能之间会互相引用**（`参照 ../别的技能/references/x.md`），目录一移，引用即失效。
3. **分类本身会变**。今天觉得该按"领域"分，半年后想按"输入类型"分——平铺结构下这只是改表格，嵌套结构下是一次大规模搬迁。

所以：**分类是元数据，不是目录层级。** 想按分类浏览，看 `CATALOG.md`；想按分类筛选，一行 `grep` 就够：

```bash
grep '| `re` |' CATALOG.md
```

> 例外：当一个技能**明确要分裂成多份独立分发的包**时（比如一个技能同时要发成 DSH 包和 Claude Code 插件），可以在该技能目录内建子目录，但 `skills/` 这一层仍保持平铺。

## 命名规范

| 对象 | 规则 | 例 |
|---|---|---|
| 技能目录名 | **kebab-case**，全小写，音节间用 `-`；与 `SKILL.md` 的 `frontmatter.name` **完全一致** | `reverse-engineering` |
| `frontmatter.name` | 同上，且必须 kebab-case（部分运行时按此校验） | `reverse-engineering` |
| `references/` 内文件 | kebab-case `.md`，按主题命名而非编号 | `chinese-legacy-stacks.md` |
| `scripts/` 内文件 | kebab-case；**Python 用 `.py`，PowerShell 用 `.ps1`** | `pe_recon.py` |
| 版本号 | `CHANGELOG.md` 用语义化版本；`SKILL.md` 的 `metadata.version` 与之同步 | `2.0.0` |

**禁止**：中文目录名、空格、大写、`v1`/`final`/`new` 这类无信息后缀。

## 分类的原则

分类**按技能要解决的问题**（功能），不按：

- ❌ 按语言（`python-技能`）——同一个技能常混用多语言
- ❌ 按创建时间（`2026-10`）——时间不是分类，是 git 能回答的事
- ❌ 按状态（`stable`/`beta`）——状态是 `CATALOG.md` 的一列
- ❌ 按使用者（`personal`）——整仓都是个人的

✅ 按**任务类型**：拿到一个任务，你会先去哪个技能里找。

## 什么算一个「技能」

同时满足：

1. 有明确的**触发条件**（`description` 能说清"什么时候用它"）
2. 有**可执行的内容**——步骤、检查表、脚本、参考表，而不仅仅是知识陈述
3. 不依赖其它技能就**能独立加载**（跨技能引用只能是软引用）

如果内容只是"某个领域的知识汇编"，放 `references/` 而不是新建技能。

## 与语料的边界

语料**不进** `skills/`。理由：语料体积大、更新节奏不同、且常被多个技能共享；放进技能目录会导致同一份内容多副本、以及公开仓误传版权内容。

技能用 `依赖语料` 声明（见 `CATALOG.md`），运行时通过环境变量解析路径。
